# 养鱼 · 策划案（DeepSeek 是大肥鱼，吃大米饭）

> 一句话：你养的是一条**替你试吃视频的大肥鱼**。它吃的是 token（大米饭），吐出来的是"这条值不值得看"。

## 1. 为什么是这个主题

把**看不见的成本**（token / API 费用）变成**看得见的饭量**。
用户不会为"每次调用 1200 tokens"付钱，但会为"这条鱼今天吃了三碗饭、捞回 9 条值得看的"付钱。
养成感负责留存，饭量负责成本透明，两者是同一个东西。

## 2. 角色与语言（全站统一）

| 概念 | 用户看到的词 | 实际含义 |
|---|---|---|
| 大肥鱼 | 鱼 / 肥鱼 | DeepSeek |
| 大米饭 | 饭、碗 | token |
| 喂饭 | 开饭 / 喂 | 开始一轮分析 |
| 鱼食 | 食 | 待分析的视频队列 |
| 吃 | 正在吃 / 嚼 | 正在分析某条视频 |
| 吐刺 | 吐刺 | 判定"不看"（刺=不值得看） |
| 鱼获 | 捞出来的 | 结论列表 |
| 鱼塘 | 塘 | 历史结论库 |
| 饿 | 饿了 / 断粮 | 没填 API Key 或额度用完 |
| 长膘 | 长膘 | 累计 token 增长（等级） |

语气：**不做幼儿化**。文案短、冷静、带一点冷幽默（"标题党，吐刺"），不卖萌、不用感叹号。

## 3. 核心循环

```
挑食（队列） → 喂饭（花 token） → 嚼（分析） → 鱼获（结论） → 采纳（点开看）
      ↑                                                        │
      └──────────── 鱼变肥（等级/口味校准） ←──────────────────┘
```

关键设计：**采纳才算"吃好了"**。只花 token 不看结果不涨膘，防止"乱喂"。

## 4. 功能清单（按优先级）

### P0 — 已经能跑，补齐"饭"的语义
- 鱼缸页：鱼的成长形象、饭碗余量、今日饭量
- 喂饭：从首页/收藏/搜索/单个视频入队，选择"碗大小"（小碗 ≈ 8 条 / 中碗 ≈ 20 / 大碗 ≈ 40）
- 吃相：逐条的阶段（取食 → 嚼 → 吐刺/吞下），实时进度
- 鱼获：评分、看/不看/也许、一句话、依据、标签、原话引用，点击直达播放
- 吐出物：**吐刺**的可视标记（不看 = 一根刺）
- 断粮：没 Key 时鱼是"饿"的，点碗进设置

### P1 — 让鱼有"口味"
- 指令（鱼的食谱）：预设 4 套 —— `严格`（默认）/ `宽容` / `只看干货` / `标题党直接骂`
- 口味校准：每条结论可点"不准"，累计后作为 few-shot 影响后续（不微调模型，只改提示词里的例子）
- 食量上限：每天/每次的 token 预算，超了就"鱼吃饱了，明天再喂"
- 跳过明显不需要的：时长 < 60 秒、纯音乐/舞蹈/游戏实况（无解说）默认不喂，节省饭量

### P2 — 让鱼自己吃
- 自动喂食：每天固定时间，只喂**新视频**（关注 + 首页），喂完把"值得看"推到消息
- 鱼塘检索：按标签/关键词/结论搜索历史，支持"我上周看过的讲 X 的"
- 周报：这周吃了多少、捞回多少、花了几碗饭、最值的一条
- 反刍：对"也许"的视频，第二天用更多材料（更多评论/更高 token）再嚼一次

### P3 — 长膘与社交
- 长膘等级：按**被采纳的结论数**（不是纯 token）升级，解锁更细的章节切分
- 鱼获卡片：导出"今日鱼获"图片（结论 + 引用 + 饭量）
- 鱼塘共享（可选）：只读分享一条结论

## 5. UI 设计

### 5.1 页面结构（沿用现有页面，不新增层级）
```
┌ 鱼缸页 ────────────────────────────────────────────────┐
│ [鱼]  养鱼 · 今天吃了 12 个 · 捞出 6 个     饭碗 ▓▓▓░░ 3/5 碗 │
│ ┌ 鱼缸条（96px）──────────────────────────────────────┐ │
│ │ 正在嚼：影视飓风员工，开什么车？          看片中 62/200 │ │
│ │ 波纹 + 游动的鱼（只在运行时动）                        │ │
│ └────────────────────────────────────────────────────┘ │
│ ┌ 鱼获（左，750）────────────┐ ┌ 鱼缸数据（右，484）──┐ │
│ │ [看][不看][也许] 行         │ │ 分数分布            │ │
│ │ 标题 / 一句话 / 标签 / 评分 │ │ 统计 + 饭量         │ │
│ │ 刺的标记在"不看"行上        │ │ 标签云              │ │
│ └────────────────────────────┘ └────────────────────┘ │
│ [食谱输入框]                       [暂停] [开饭]  [刷新] │
└────────────────────────────────────────────────────────┘
```

### 5.2 鱼的形象
- **SVG 三层**：身体（椭圆+尾鳍）、眼睛、腮线；不用位图，随等级缩放
- 成长 5 阶：鱼苗 → 小鱼 → 圆鱼 → 胖鱼 → 大肥鱼（体宽 44 → 96px，尾鳍摆动幅度递增）
- 状态：`饿了`（眼睛半闭、肚子扁）、`嚼`（腮部一鼓一鼓，只在运行时）、`吃饱`（肚皮朝上打嗝，3 秒后恢复）
- 颜色：主色沿用强调蓝，**饭碗用暖琥珀色**（唯一新增色），因为它代表"钱"

### 5.3 饭碗（token 可视化）
- 一条 5 格的横向饭格，每格 = 预算的 20%
- 每喂一条，掉一格的一小片（不是整格跳），有 120ms 的落下动画
- 鼠标悬停显示真实数字：`已用 42.1k / 60k tokens（约 3 碗）`
- 断粮：饭碗空 + 一个锁孔图标，点击进设置填 Key

### 5.4 结论行的"刺"
- "不看"的行右侧一根 12px 的细刺（1.5px 描边，灰），hover 变红
- 一行最多一根，避免视觉噪音

### 5.5 动效预算（性能红线）
- 只有**鱼缸条**在运行时有一个 40ms 定时器（波纹+鱼），暂停即停
- 饭碗、刺、结论行：全部是状态驱动，无定时器
- 页面空闲时零重绘

## 6. 数据

沿用 `fish.db`（已实现），新增两张表：
- `meals(id, at, bowl, videos, tokens_in, tokens_out, adopted)` —— 每次喂饭的账单
- `feedback(bvid, at, kind, note)` —— 用户"不准"的反馈，用于校准 few-shot

## 7. 指标

| 指标 | 目标 | 说明 |
|---|---|---|
| 喂饭后 24h 内的采纳率 | ≥ 25% | 鱼获里点开播放的比例（核心价值） |
| 单位饭量的采纳数 | ≥ 0.8 条/千 token | 衡量"饭是否值" |
| 断粮率 | < 10% 天数 | Key 失效/额度不足 |
| 鱼塘复访 | 7 日 ≥ 35% | 养成是否成立 |
| 吐刺准确率 | 人工抽检 ≥ 80% | 判"不看"的视频里，用户认可的比例 |

## 8. 风险

1. **结论不准** → 校准 + 预设食谱 + 只喂长视频（材料更足）
2. **饭太贵** → 碗大小 + 日预算 + 默认中碗 + 跳过短内容
3. **太萌不可信** → 文案冷静、不用 emoji、结论带引用
4. **B 站风控** → 转写接口 1.5s 间隔 + 退避（已实现）
5. **材料不足**（无转写）→ 明确标注"只靠评论判断"，并降低该条结论的置信显示
